## 一、任务卡

- **类型**：L（跨 5 个文件以上）
- **需求原句**：「回执里的轮数保留作为参考，从前面讲的批次的口径取，文档里的按你说的改；子代理隔离脏活、只重跑失败用例这两个加上」
- **验收句**（做完可逐条判定）：
  1. 回执三行齐备：`轮数（批次·仅参考） ｜ 请求 ｜ 上下文` + 搜索/读取 + 成本；轮数由 hook 计量后注入、模型抄写，不再自报；「输入累计」**不进回执**（与成本行的「输入」是同一个数），只用于档位判定；
  2. 会话累计输入达到 400k / 800k / 1.2M 时，工具结果里分别出现提示、分析、交接摘要；
  3. 全部为注入文字，**不新增任何 deny**；
  4. `docs/task-routing.md` 有「探索型任务交子代理」判据与量化收益；`guard_pytest` 在同范围重跑时注入「只重跑失败文件」；
  5. `tests/test_hooks_contract.py`、`tests/test_rules_guard.py` 全绿；`RULES.md` 仍 ≤100 行（现 96）。
- **轮数上限**：≤15 请求、累计输入 ≤1.2M；上下文 >40k 且任务未完时先出交接摘要再继续。

## 二、已定结论（不要重开讨论）

1. **并行不省请求、不省 token**：实测 10:30:23 与 10:30:32 两次并行 Read 产生 2 条 usage，ctx 47,390→50,605（已含第一个文件内容）。并行只省墙钟时间。
2. **轮 = 批次**：同一批的并行调用合并为 1 轮（实现取「与上次调用间隔 ≤3 秒」为同批），只作参考；**预算与检查点一律按「请求数 + 累计输入」**。
3. **成本结构**：固定底座 19,570 × 请求数占 32%，历史累积重发占 68%，单条新增均值 1,958 token。上下文封顶 40k 可省 36.2%（47 条实测 284.1 万 → 181.3 万）。
4. **hook 只计时与注入，不做预算类 deny**：一次 deny ≈ 一整个上下文（约 6 万），是注入的 40 倍。
5. 现有三类判重（`guard_read` 区间 / `guard_search` 键 / `guard_pytest` 范围）保持不变。
6. **子代理隔离**：探索型脏活放子代理，主对话只收摘要。本次实测：`token-analyst` 4 条请求跑在 21k→25k 底座上，约 6 万；同样的活主对话做（每条带 60k+ 底座）约 24 万，省 75%。
7. **只重跑失败用例**：上个会话 pytest 4 次共 34 万，其中 2 次是 `# rerun` 全量重跑；改为「全量 1 次 + 只跑失败文件」可省约一半（17 万）。
8. **回执不写「输入累计」**：与 `- 成本：输入 X + 输出 Y = 合计 Z` 重复。累计输入只在内部用于 400k / 800k / 1.2M 档位，到档时才出现在文案里。
9. **回执首行不带「/ 上限」**：`- 轮数：3 ｜ 请求：4 ｜ 上下文：20,447→44,057`。现 `guard_stop.py` 的 `ROUND_LINE_RE` 强制 `数字/数字`，**必须同步放宽**（`轮数：` 后接数字，`/上限` 改为可选），否则每条回复都会被 Stop 判「缺轮数行」。
10. **回执仍是四行**（`回执：` + 三行项目符号）：成本行不能删，`COST_LINE_RE` 仍按它校验；删了会触发 Stop block，`loop_limit: 2` 用尽后每轮白烧一次完整上下文。

## 三、改动链（4 片，逐片验证）

### 片 1 · 口径与模板
- `RULES.md` §零.3：回执行改为
  `- 轮数：3 ｜ 请求：4 ｜ 上下文：20,447→44,057`
  —— 轮数按「批次」口径（同批并行算 1 次），不带 `/上限`；**随之必须改 `guard_stop.py` 的 `ROUND_LINE_RE`**：允许 `轮数：\d+`（`/\d+` 可选），否则新格式全部被判「缺轮数行」。
- 回执仍必须保留 `- 成本：输入 X + 输出 Y = 合计 Z` 行（`COST_LINE_RE` 的校验对象）。
- `RULES.md` §二：「第 6 轮检查点」改为「第 12 次请求仍未跑通即停」；预算主口径写「请求数 + 累计输入」。
- `.trae/rules/project-rules.md`：同步回执的四行结构与字段名（现 32 行），保留「回执四行」的措辞，别写成三行。
- `docs/task-routing.md`：加预算档位表 + 一句「并行只省时间不省钱」+ 子代理判据（见片 4）。
- `docs/token-cost.md`：补「轮 = 批次（仅参考）」「累计输入 = 本会话起点至今 prompt_tokens 之和」两条口径。
- **配额注意**：RULES 现 96 行，净增 ≤4，新增句子须等量删旧句。

### 片 2 · 计量与注入
- 新建 `.trae/hooks/guard_budget.py`，挂 PreToolUse（matcher 留空或列全工具名）：
  - 从 `data/llm_usage.jsonl` 取本会话起点（槽里的 `created_ts`）至今所有 `prompt_tokens` 求和，作为「累计输入」——只在档位文案里出现，**不进快照、不进回执**；
  - 轮数：`_state` 里记 `last_call_ts`，与本次间隔 ≤3 秒视为同一批，否则 `batches += 1`（并行调用通常同秒落状态；取 1 秒偏紧，任一 hook 卡到 10s timeout 会把一批拆成两批）；
  - 每次注入一行快照 `轮 5 ｜ 请求 12 ｜ 上下文 38k→47k`，模型直接抄进回执；`first_ctx` 在槽里首次写入，`上下文` = `first_ctx → 上一条请求的 prompt_tokens`；
  - 快照与累计输入会把子代理请求一并计入（子代理同样写 `llm_usage.jsonl`，只能按时间归类）。这是真实花费，不剔除；但 800k 档分析里单列「其中子代理约 X」，避免把「提前触发交接」误读成模型乱跑；
  - 按 400k / 800k / 1.2M 三档升级文案：
    - 400k：一行（已用 / 剩余 + 合并建议）
    - 800k：5 行分析（Top3 object、重复项、可省估算）
    - 1.2M：交接摘要模板（已完成 / 未完成 / 下一步 / 约束 / 读取起点）
  - 未到档位只出快照一行；读不到日志 fail-open。
- 改 `.trae/hooks/guard_reset.py`：现在用户新消息会整槽 `sessions.pop()`，改为保留槽、只清空 `reads/searches/cmds` 并把请求数 / 批次数归零。**`created_ts` 与 `first_ctx` 不重置**——用户发第二句话时上下文并没有归零（上个会话第二段起点 ctx 已 44k），跟着重置会让「累计输入」永远打不到 800k / 1.2M，正好漏掉最贵的场景。
- `.trae/hooks.json` 加条目。
- 验证：用临时 `llm_usage` 夹具造三档数据，断言文案正确且无 deny。

### 片 3 · 上下文封顶 + 失败重跑提示
- `guard_budget.py`：单条 `prompt_tokens` >40,000 时追加「上下文已 40k+，剩余任务 >5 条建议换会话」，并附交接摘要模板。**必须分档去重**：槽里记 `last_ctx_warn`，只在跨过 40k / 60k / 80k 时各注入一次，中间只出快照一行；否则上个会话 47 条里约 40 条各带一次模板（≈2 万 token），高频重复还会让模型对提示脱敏。
- `guard_pytest.py`：同范围第二次（带 `# rerun`）放行但在 `additionalContext` 注入「只重跑失败文件：`pytest <失败文件>`」；判重逻辑不变。
- 不新增 deny。

### 片 4 · 子代理隔离规则 + 测试与记录
- `docs/task-routing.md` §四增一条判据：**探索型、信息量大但结论短**（跨 ≥2 模块定位、日志/数据探查、token 复盘）→ 交子代理，主对话只收摘要；理由是主对话每条都带全量上下文，子代理在低底座上跑，实测省 75%。
- 「子代理」必须点名，不留执行时的二次判断：

  | 脏活 | 交给谁 | 备注 |
  |---|---|---|
  | token 复盘 / 成本拆解 | `token-analyst` | 只读，能跑 python 聚合 |
  | 有现象要追根因、跨 ≥2 模块 | `bug-reproducer` | 前提是**已有现象**；它会写失败用例并跑 pytest，纯探索别用 |
  | 需求 → 可验收方案 | `planner` | 口径不清时 |
  | 页面形态 / 交互未定 | `page-prototyper` | 纯后端不进 |
  | 纯探索（找实现位置、翻日志找规律、扫配置） | `general_purpose_task`（内置） | 4 个自定义代理里没有「只找不修」的角色 |

- 子代理 ≠ 新开会话：前者在低底座独立跑、只把摘要带回，主对话上下文不丢；后者清空上下文，只用于 1.2M 交接。
- 子代理不继承主对话上下文，提示词必须带「背景 / 现象或需求原句 / 验收句 / 边界」四要素；判重槽按 `session_id` 分开，子代理读过的文件主对话再读不会被 hook 拦，**主对话侧不要再整读核对**。
- （已完成）4 个 `.trae/agents/*.md` 的回执段与 `docs/task-routing.md` §四的回执约定已统一为「轮数/请求 · 搜索读取/输出峰 · 写入命令/成本」，与主回执同构；子代理侧成本记「未计量」，由主对话按 `llm_usage` 补齐。
- `RULES.md` §二加半句「探索型脏活交子代理」，与片 1 的行数配额一并算。
- `tests/test_hooks_contract.py`：新增 `guard_budget` 三档 + 无 deny + fail-open + 轮数按批次合并的用例；`guard_pytest` 注入提示用例；`guard_stop` 新回执格式（`轮数：3 ｜ …`，不带 `/上限`）放行、缺成本行仍 block 的用例。
- `tests/test_rules_guard.py`：断言 RULES 行数 ≤100、回执模板含 `请求：` 与 `上下文：`（不再要求 `输入累计：`）。
- `CHANGELOG.md` 一条（v1.94）。
