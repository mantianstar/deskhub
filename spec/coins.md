## 14.1 目标与成功标准

| 项 | 结论 |
|---|---|
| 使用者 | 仅本人（同统一约定，无账号体系） |
| 要解决的问题 | 我每天要手动在麦稀奇上翻专场，凭记忆判断「这条是不是我常买的品类、值不值这个价」，费时且容易漏 |
| 形态 | 本工作台里的一个正式模块（原为占位页） |
| 数据源 | **麦稀奇（mxiqi.com）** 的专场 / 拍品 / 站内历史成交（走其小程序网关，见 §14.3）；**硬币目录信息**另接 Numista（见 §14.13） |
| 成功标准 | 连续多天主动打开它，且**至少有一次靠它避免买贵、或发现了本来会漏掉的专场** |
| 首要风险 | ① 网关接口变更 / 不可用 → 采不到数据；② 推荐价算得离谱 → 我不敢信，模块作废 |

模块由**两条互不依赖的管道**组成：

| 管道 | 数据源 | 回答的问题 | 章节 |
|---|---|---|---|
| **拍卖** | 麦稀奇小程序网关（免登录、免浏览器） | 谁在卖、这场有没有我要的、值多少 | §14.3~§14.12 |
| **参考库** | Numista 公开 API（+ 类型页 CDP 取数） | 这枚币本身是什么、多大、多重、发行量多少、各品相市价与稀有度 | §14.13~§14.15 |

两条管道的页面并列但不互链：拍卖页在 `/coins`，参考库页在 `/coins/info`、`/coins/manage`。

## 14.2 收藏画像（来源与形态）

- **来源**：`data/orders.xlsx`（麦稀奇历史成交导出，实测 1567 条；列为「订单号 / 店铺名称 / 宝贝名称 / 宝贝价格」）。
- **解析**：对每条「宝贝名称」用 LLM 抽结构化字段：国家/地区、年代（年份或年号）、面值、品类、品相/包浆；价格直接取「宝贝价格」。
- **聚合**：按维度统计频次与价格分布 → 得到「我在买什么」的权重表。
- **形态**：结构化标签**入库**，作为**未建立收藏系列时**的兜底画像；旧版标签编辑页面已于 2026-10-19 移除，
  标签仍由 `coins-parse-orders` 生成，匹配逻辑不变。
- **画像维度**：国家/地区 · 年代 · 面值 · 品类 · 品相/包浆 · 偏好店铺 · 价位区间。
- 画像改动**次日生效**，不追溯修改历史推荐。

> 维度来自实际订单名的形态：「东加勒比1959年一分」→ 国家=东加勒比、年代=1959、面值=一分；「康德四年一分」→ 国家=满洲（康德）、年代=康德四年；「英国1919年半便士」→ 国家=英国、年代=1919、面值=半便士。

## 14.3 拍卖：数据源（麦稀奇）与访问边界

**用到站点的三处能力**（都是小程序网关）：

| 用途 | 位置 |
|---|---|
| 专场列表（预展 / 进行中） | 小程序网关 `gapi.mxiqi.com` → `miniprogram.auction.ListAuction` |
| 专场详情（拍品、押金、拍品数、围观数、店铺、**开拍 / 截拍时间**） | 小程序网关 → `miniprogram.auction.get` |
| **站内历史成交**（按关键词搜成交量） | 小程序网关 → `miniprogram.home.filter`（`search_params.keywords` + `status=2`） |

三处**全部**走小程序网关：**免登录、免签名、免浏览器**，普通 JSON POST 即可。
「拍卖时间」按专场类型：**实时专场 = 开拍时间（`start_time`）**，**限时专场 = 截拍时间（`end_time`）**。

> 网页端 `www.mxiqi.com` 是 JS 单页应用 + 阿里云滑块，对非浏览器请求做风险拦截（直连只返回验证页）——
> **但小程序网关不设这道墙**，上面的三个接口普通请求就能取到。

**访问边界**：

- ✅ 只用小程序网关的**公开读写接口**（`ListAuction` / `get` / `home.filter`），不碰网页端与滑块。
- ✅ **限量、限速**：请求之间留间隔（`request_interval_seconds`），查价另有更保守的间隔与单轮上限
  （`coins.price.query_interval_seconds` / `max_queries_per_run`），不整站遍历。
- ❌ 不做：浏览器渲染 / 反爬对抗 / 自动破解验证码（**不需要**）。
- ❌ 不做：存储我的账号密码或登录凭据。**成交价也不需要登录**（`home.filter` 未登录即可取成交）。
- ❌ 不做：对站点的越权访问或高频请求。
- 失败不静默：接口报错会记 `coin_fetch_runs`（`http_error` / `parse_error`）并在页面上标注「数据更新至 X 时间」。

> 与「只接 RSS/公开接口」的统一策略一致：本模块也只接麦稀奇的**公开接口**，不属于「反爬」范畴。

## 14.4 拍卖：每日管道

1. 取 `enabled=1` 的画像标签
2. 抓当前专场列表：**预展 + 进行中**（实时 + 限时两类都取），但**实时专场只保留开拍时间、限时专场只保留截拍时间落在业务时区「今天」的专场**（§14.17）
3. 逐场抓详情 → 拍品（名称 / 图 / 起拍价 / 当前价）+ 专场元数据（押金 / 拍品数 / 围观数 / **开拍或截拍时间** / 店铺 / 认证）
4. 用画像匹配每条拍品名 → 命中则记为「推荐拍品」，累加匹配分
5. **只展示至少命中 1 条推荐拍品的专场**（数据仍**全量入库**，便于画像改动后重新匹配，不必重抓）
6. 对每条推荐拍品算推荐价（见 §14.6）
7. 落库，生成页面

**幂等**：以麦稀奇的专场 id / 拍品 id 为去重键，重复抓取不产生重复行。
**失败隔离**：单场失败只记日志，不影响其余专场（见 §14.3）。

## 14.5 拍卖：数据模型（与知识聚合的表无外键关联）

概念模型如下（落地 DDL 见 [plan/coins.md](../plan/coins.md) §18.7）：

- `coin_orders`：历史订单解析结果（订单号、店铺、宝贝名称、价格、抽出的结构化字段）
- `coin_profile_tags`：画像结构化标签（维度、值、权重、命中数、是否启用、备注）——**可编辑**
- `coin_collection_series` / `coin_collection_series_members`：收藏系列与 Numista series 的手工映射（§14.17）
- `coin_shops`：店铺（麦稀奇 uid、名称、头像、认证标识）
- `coin_sessions`：专场（麦稀奇 id、店铺、专场名、状态、拍卖时间、押金、拍品总数、围观数、封面图）
- `coin_lots`：拍品（专场、麦稀奇 id、Lot 号、名称、起拍价、当前价、图片、标签、匹配分、是否推荐）
- `coin_price_refs`：推荐价的取证记录（拍品、搜索关键词、成交样本数、P25 / 中位数 / P75、原始命中、查询时间）
- `coin_fetch_runs`：采集日志（kind、目标、起止时间、状态、HTTP 码、新增数、错误）

## 14.6 拍卖：推荐价格口径

- **数据来源**：麦稀奇站内**历史成交**（`home.filter`，`status=成交`），**不是**我个人的历史成交。
- **关键词**：从拍品名抽核心词（国家 + 年代 + 面值/品类），去掉「包老保真」「美品」这类营销修饰词。
- **统计**：取命中成交量，主推荐价 = **中位数**，并给 **P25–P75 区间**；同时记录样本数。
- **红线**：
  - 样本 < 3 条 → 只给区间并标注「样本不足」，**不给单一推荐价**。
  - 无成交样本 → 明确标注「无成交样本」，**绝不编价**（宁可空着，也不给不可验证的数字）。
  - **关键词必须包含「面值/品类」**：命中里只有国家 / 年代时关键词太泛
    （实测：「1961」抓到一堆不相干的 1961 年币；「巴拿马 1967」把**当前价 ¥330 的精制银套币报成 ¥2**），
    这类**主动不报价**，页面标「未报价」。
  - 面值/年代这类**以数字开头或结尾的值，不许咬进更长的数字**：「5分」不得命中「25分」
    （实测同一个 bug 让「美国 1962 年 25 分」按 5 分去查价）。
- **可追溯**：每条推荐价都能点开看到用了哪个关键词、命中了哪几条成交（`coin_price_refs`）。
- **不做**：不做「AI 直接给买入/卖出指令」；本模块只给**参考价区间**，决策仍在我。

## 14.8 拍卖：调度

- 随服务常驻；**每天 07:00 与知识日报同批**执行（采集、回采、查价各有一个定时开关；匹配不参与定时任务，可在运行控制页手动重跑，见 [core.md](./core.md) §9）。
- **不做启动补拉**；本机休眠期间不跑、接受漏天，要立刻跑就手动触发（`/control` 或 CLI）。
- 采集限量限速（见 §14.11）；**铜币任务的失败不影响知识日报**。

## 14.9 拍卖：风险与对策

| 风险 | 对策 |
|---|---|
| 网关接口变更 / 不可用 → 采不到数据（首要风险） | 接口报错**显著记录**而非静默；页面标注「数据更新至 X 时间」；站点耦合集中在 `gapi.py` 一处，改版只改这一处 |
| 推荐价离谱 → 不敢信（首要风险） | 只给区间 + 样本数 + 可追溯证据；样本不足则明确不报价 |
| 画像失准（LLM 抽错品类 / 年代） | 画像可编辑；先人工校对一遍再启用；错抽的标签关掉即可 |
| 与知识模块相互拖累（采集卡住进程） | 两条管道各自独立任务、各自超时与隔离；铜币采集失败不阻塞 07:00 知识日报 |
| 麦稀奇改版导致字段变化 | 站点接口与字段映射集中到 `app/coins/gapi.py`，改版时只改这一处 |

## 14.10 拍卖：开发顺序

1. **先画像**：跑通 `orders.xlsx` → 结构化标签 → 可编辑（此时还没碰麦稀奇，零风险）
2. **再打通采集**：把小程序网关的接口跑通，能稳定拿到专场及其拍品（**最大不确定性，先单独验证**）
3. **上匹配与定价**：画像筛专场 + 站内成交搜价
4. **最后做页面**（顺序搞反会得到一个漂亮的空壳）

## 14.12 拍卖：验收标准

1. `orders.xlsx` 能解析出订单，画像标签入库且**可在页面上编辑**
2. 每天能采到当日「预展 / 进行中」专场与拍品并入库
3. 画像能筛出相关专场，**无命中则为空态**（不展示无关专场）

## 14.13 铜币参考库（Numista）

> 与 §14.3 的麦稀奇**互不依赖**：那一节管「拍卖」（谁在卖、卖多少），本节管「**硬币本身**」（这枚币是什么、多大、多重、发行量多少）。
> 来源是 **numista.com**：目录信息走公开 API v3；估值与 Frequency 走类型页（接口里没有，见 §14.13.4）。

### 14.13.1 能力与三处采集

三处能力对应三个 CLI 命令（输入是中文，接口是英文，自动转换）：

| 命令 | 输入 | 产出（落库） |
|---|---|---|
| `coins-series` | 国家 + 年份 + 面值 | **系列信息**：系列号、系列名称、网页链接、大类、国家、系列起止年份、执政者、面值、尺寸、厚度、形状、材质、正面描述/铭文/图片、背面描述/铭文/图片、目录号 |
| `coins-issues` | 系列号 | 该系列**全部年份的单版**：单版编号、年份、公历年份、造币厂、厂标、版别备注、补充备注、发行量、尺寸、重量、厚度、币边、是否精制、是否样币、图片 |
| `coins-values` | 系列号 | 该系列每个单版的**各品相估值**（G/VG/F/VF/XF/AU/UNC）+ **Frequency**（走类型页，见 §14.13.4） |
| `coins-images` | 系列号 | 该系列**正 / 反图**下载到本地（走类型页 CDP 链路，见 §14.15） |
| `coins-translate` | 可选 `--series-id N` | 读**英文表**重翻**中文表**（不重采 Numista、不耗接口额度，见 §14.13.3） |

- **中文→英文转换**：国家走内置映射（`ISSUER_CODES`）到 Numista 的**本国** code（英国=`royaume-uni`）；面值走单位映射 + 数字前缀（「1便士」→「1 penny」、「半便士」→「half penny」）。**不调 LLM**（无 token 成本）；未收录的国家**明确报错**，不猜（猜错会静默返回别国的币）。
- **存取**：`coin_series` / `coin_issues` / `coin_issue_values` 按 Numista id **幂等 upsert**（重抓不增行）。
- **站点接口事实（实测，务必按此避免踩坑）**：
  - 搜索 `GET /types` 的年份参数是 **`year`（单年）**，**不是** `min_year`/`max_year`（实测这两个被忽略）。
  - 单版在**独立端点** `GET /types/{id}/issues`（返回裸数组），**不是** `/types/{id}?includeIssues=1`。
  - 发行方 code 是**法文式 slug**，且「伞级」`united-kingdom` 会含百慕大等属地，本国是 `royaume-uni`。
  - `q` 只做**模糊匹配**（查 `1 penny` 会连 `½ Penny` 一起返回）。
- **目录号取全**：`references` 里**每一条**都取，写成 `目录代码#编号` 逗号分隔（如 `KM#790,Sp#3961`），不只取 KM；系列与单版都存。

### 14.13.2 访问边界与风控

- 只用 Numista 公开 API（带 Key），请求之间**限速**；Key 走环境变量 `DESKHUB_NUMISTA_API_KEY`（只写变量名，真实值在 `.env`）。
- 系列详情请求有配额，单次搜索默认最多取 10 个系列（`coins.numista.max_series`）。
- **额度自管**（免费额度每月 2000 次，且响应**不带限流头**，只能自己数）：请求间隔 + **单轮上限**（`max_requests_per_run`，默认 40）+ **月度上限**（`monthly_limit`，默认 1500，留 25% 余量，按业务时区切月）；每次请求落 `coin_api_usage` 计数，CLI 会打印本月用量。
- 类型页相关命令（`coins-values` / `coins-images`）**不占接口额度**；因为要本机开着带调试端口的 Chrome，**不进每日调度**（Frequency 变化很慢，采一次能长期用）。

### 14.13.3 中文化（枚举走词表 + 长文本走大模型）

另存 `coin_series_cn` / `coin_issues_cn`，**列数与英文表完全一致**，只把可翻译字段注成中文——系列：`title / object_type / issuer / ruler / denomination / shape / composition / edge / obverse_desc / reverse_desc / comments / mints / commemorated_topic`（`series` 为名称列表，逐条翻译）；单版：`mint / comment / edge`；其余字段原样复制。翻译分两条路：

- **枚举类字段**（`object_type / issuer / ruler / denomination / shape / composition / edge / mints / mint`）→ **内置词表**（离线、免费、零依赖，且是采集时「按面值 / 材质过滤」的依据），命中即精确成中文。
- **描述 / 备注 / 名称**（`title / obverse_desc / reverse_desc / comments` + 单版的 `comment`）→ **大模型翻译**（词表只能做术语替换，长句会中英混排）。一个系列的长文本合成**一次**请求、该系列全部单版备注合成**一次**请求。**没配 `DESKHUB_LLM_API_KEY` 或调用 / 解析失败 → 回退内置词表结果**（采集不中断，只记一条 warning）。
- **剥 HTML**：Numista 的 `comments` 是 HTML 片段（`<p>` / `<br>` / `<i>` / `<strong>`），而页面用 Jinja **自动转义**渲染 —— 不剥掉就会把标签当**字面文本**显示。故中文表落库前统一剥成纯文本；**英文表保留原文**不动。
- **存量重翻**：`coins-translate [--series-id N]` —— 读**英文表**做输入、重翻后覆盖**中文表**，**不重采 Numista、不耗接口额度**。无 Key 时明确报错。

### 14.13.4 各品相估值 + Frequency

- **口径**：类型页表格里的**每个年份（含版别）× 每个品相（G/VG/F/VF/XF/AU/UNC）的估值**，以及 **Frequency**（在所有拥有这枚币的用户中，拥有该年份/品种的用户占比，百分数；同一用户可有多个版别，故同一类型下总和可能 >100%）。
- **接口里没有这两项**（`/types/{id}` 与 `/types/{id}/issues` 的字段里既无 frequency 也无按品相的值）——它们只出现在**类型页的表格**里，故采法定为**读页面**：一次页面加载就拿到**整个系列**的价格与 Frequency，**不占接口额度**。
- **页面挡着 Cloudflare 的 JS 校验**：`curl`、`httpx`（带完整浏览器头）、`curl_cffi`（指纹伪装）**一律 403**；Playwright 自己 launch 的 Chrome（headless / headful）也过不去。**只有挂到你用调试端口开的正常 Chrome（CDP）能拿到页面** —— 所以这条链路要求本机开着 Chrome（`coins.numista.cdp_url`，默认 `http://127.0.0.1:9222`），**不做无人值守调度**。
- **币种不写死**：估值按**访客币种**渲染，币种写在表下 —— 随数据一起**读出来存下来**（`coin_issue_values.currency`）。
- **没值的格子留空**：精制版、少见品相本来就没有估值 → 存 `NULL`，不臆造（同 §14.6 精神）。

### 14.13.5 面值 / 材质过滤

`/types` 的 `q` 只做模糊匹配，且**没有面值筛选参数**（`denomination` / `value` / `currency` 传了都被**静默忽略**）；只有 `material=<id>` 能按材质筛，但要维护「中文材质 → id」映射，**未采用**。故采集定为**取详情后精确过滤**：

- 用详情里的 `value.text`（面值，如 `1 Penny` / `½ Penny`）与 `composition.text`（材质，如 `Bronze`）与查询条件比对，**不匹配的系列不落库**（多余的系列没有用）。
- 比对口径与页面本地筛选**共用一份实现**（`app/textmatch.py`：去空白、转小写、`½→half` 等分数符号展开、数字边界），**不分叉**。

### 14.13.6 字段缺口与诚实标注

Numista 单版接口只给 `year / mintage / comment / mint_letter / references / marks`，**没有**造币厂名、版别备注、重量、厚度、币边、是否精制/样币、单版图片。故：

- 尺寸 / 重量 / 厚度 / 币边用**系列层**值兜底；厂标取 `mint_letter`；精制/样币按备注关键词（proof / essai / pattern）标注。
- API 确实没有的**留空，不臆造**（同 §14.6 精神：宁可空着，也不给不可验证的值）。

## 14.14 铜币信息页面（浏览 + 采集触发）

## 14.15 Numista 图片本地缓存

**为什么需要**：§14.14 的详情页要显示系列正反图，但 Numista 的图片 URL 响应带 `cross-origin-resource-policy: same-origin`，浏览器会以 `ERR_BLOCKED_BY_RESPONSE.NotSameOrigin` **必然拦截**跨站 `<img>`；而裸 `httpx` / `curl` 抓又吃 Cloudflare 的 403。**页面里没法外链，服务端也抓不到** —— 唯一可行的路是把图**下载到本地**再读，下载只能借 §14.13.4 那条 CDP 链路（你自己开的、已过 Cloudflare 的 Chrome）。

| 项 | 结论 |
|---|---|
| 命令 / 按钮 | CLI `coins-images --series-id N [--cdp URL]`；网页上管理页结果行的「**④ 下载图片**」（与 CLI 同一函数，同步等待）；手工按需，**不进每日调度**（要浏览器） |
| 存放 | `data/coin_images/{系列号}-{obverse\|reverse}{原后缀}`；`data/` 不入库，删掉即失效、重跑即重下 |
| 读取 | 路由 `GET /coins/series/{id}/image/{side}` 从本地文件返回；没缓存返回 404 |
| 页面 | **缓存过才渲染 `<img>`**；详情页未缓存的一侧显示「原图链接」（自己点），信息页列表卡未缓存的一侧给占位块，均不出现破图 |
| 放大 | 详情页的正反图**点击可放大**（原生灯箱：点图开全屏遮罩 + 原图，点遮罩 / 再点图 / `Esc` 关闭；无框架、无 CDN） |
| 表结构 | **不改**：靠「文件是否存在」判断，不新增列 |

## 14.16 历史购买品相录入

> 定位：给**已经买过**的币补一档品相。数据来自 §14.2 的历史订单（`coin_orders`）；
> 与拍卖（§14.3~§14.12）、参考库（§14.13~§14.15）都不互链，是一个**人工录入**页。

**要解决的问题**：`orders.xlsx` 里只有订单名与价格，硬币的**品相**没地方记；
想「这个国家 / 年份 / 面值，我手上这枚是什么品相」时无从查起。

**做法**

- **国家 / 年份 / 面值按 Numista 口径统一**：历史订单里的 `country` / `era` / `denomination` 是 LLM 从订单名里抄的
  **原样片段**，形态很杂，先统一再展示、再去重：
  - **国家**：去殖民时期前缀（`英属新西兰` → `新西兰`、`英属澳大利亚` → `澳大利亚`、`荷属东印度` → `东印度`）。
  - **年份**：去「年 / 年度」后缀只留数字（`1910年` → `1910`）；**日本年号**换算成**公历年**
    （`明治十五年` → `1882`、`大正六年` → `1917`，与系列的 `gregorian_year` 对齐，避免同数字年号混淆）；
    其余年号取年号后的年份数字（`康德四年` → `4`、`康德元年` → `1`）；
    只有年号没有年份数字的（`光绪`）**原样保留**。
  - **面值**：前导数字转阿拉伯数字、与单位之间加一个空格（`1便士` → `1 便士`、`一分` → `1 分`、
    `二十文` → `20 文`、`壹圆` → `1 圆`、`1/4安娜` → `1⁄4 安娜`、`¼安娜` → `1⁄4 安娜`、
    `四分之一安娜` → `1⁄4 安娜`、`半便士` → `半 便士`）；`安那` 统一写成 `安娜`；
    认不出前导数字的（`当制钱十文` / `大便士`）**原样保留**。
  - 统一后的值是**去重键**，也是落库键；`coin_orders` 本身一行不改（它是订单级原料）。
- **去重**：历史订单按「国家 + 年份 + 面值」（统一后）去重；`country / era / denomination`
  **三者缺一的行不列出**（拼不出可辨认的币种）。品相记录另有两列**发行系列 / 发行主题**（纪念币用，
  如 `亚运会` / `女排`）：订单侧没有这两个值（恒为空串），具名品相行与旧的空串行**各自成行、互不覆盖**。
- **查询**：按国家 + 年份 + 面值 + **品相**查去重后的组合，四者都可空；国家 / 年份 / 面值的查询词先按同一口径统一再匹配
  （输入 `1910年` 也能命中 `1910`），匹配为**宽松包含**；品相按 好 / 普通 / 差 精确匹配。
- **录入**：每行一个下拉，取值 **好 / 普通 / 差**（另有「未录入」表示清空）。
- **新增**：历史订单里没有的组合（如还没在麦稀奇买过的币）可手工补一条 —— 国家 + 年份 + 面值 + 品相
  **四项都必填**；另可填**年号（可空）**，用于年号纪年的年份换算（`年份=6` + `年号=明治` → 公历 1873），
  年份本身是 4 位公历年时忽略年号；**发行系列 / 发行主题（可空）**用于区分同国家同年同面值的多个纪念币
  （名称是拍品精准匹配的硬门槛，见 §14.17.5）；年份 / 面值同样统一后入库，该组合随即出现在列表里（订单数 0）。
- **删除整行（清理历史错误数据）**：行尾「删除」= 清掉该组合在 `coin_orders` 里的**全部订单**（含不同写法）
  + 该组合的品相记录；**需二次确认**（第一次点变「确认删除」并给「取消」，再点才提交）。
  具名行（有发行系列 / 发行主题）的删除只清品相记录，不动订单（订单本身没有这两个值）。
  注意：重跑 `coins-parse-orders` 会把 `orders.xlsx` 里的订单重新导回来；画像标签也不会自动重算。
- **保存**：一个「保存」按钮保存整张表；下拉选「未录入」即清除该组合的记录；旧表单不带发行系列 / 发行主题列时按空串补齐。

**落库**：独立表 `coin_purchase_grades`（`(country, era, denomination, theme, coin_name)` 唯一，
一个组合一条；`theme` / `coin_name` 为 `NOT NULL DEFAULT ''`，迁移时旧行统一置空串，不做推断）。
**不写 `coin_orders.condition`** —— 那是订单级、由 LLM 抽的包浆描述，覆盖会污染画像；
本表是画像「已有年份」的**唯一依据**：品相按 好 / 普通 / 差 三个值匹配，`差` 另进需升级列表；
未录入（有订单但实物缺失）不算已有，计入缺失年份。
画像回填已有年份时，品相行的 `theme` / `coin_name` 分别对应 Numista 系列的
`issue_series` / `issue_theme`：双方都有值才要求相等，一侧留空视为不限。
面值取**该成员**（Numista 系列）的面值，成员无面值时退回收藏系列的面值 ——
一个收藏系列可以挂多个不同面值的成员，各成员按各自面值匹配品相行。

**页面**

| 页面 | 路由 | 内容 |
|---|---|---|
| 品相台账 | `/coins/grades` | 查询表单（国家 / 年份 / 面值 / **品相**；国家 / 面值可输入 + 候选下拉，品相为下拉 全部 / 好 / 普通 / 差；**筛选条吸顶**）→ **新增组合表单**（国家 / 年份 / 面值 / **主题（可空）** / **名称（可空）** / 品相）→ 去重组合表（国家 / 年份 / 面值 / **主题** / **名称** / **所属收藏系列**（派生列，按国家 + 面值匹配，不落库）/ **品相下拉** / **操作：删除**）→ **底部「保存」（吸底）** |
| — | `POST /coins/grades/add` | 手工新增一条组合（国家 / 年份 / 面值 / 品相必填，主题 / 名称可空；键不完整或品相非法 → 400）；页面内带 `fragment=1` 时只返回结果片段（局部刷新：上方查询条件与表单里填的内容不变，仅下方结果按当前筛选重查） |
| — | `POST /coins/grades/delete` | 删除整行：清掉该组合的全部历史订单 + 品相记录（键不完整 → 400；具名行只清品相记录）；**前端二次确认后才提交** |
| — | `POST /coins/grades/save` | 保存整表：逐行按 5 列 upsert；下拉为「未录入」则删除该行；主题 / 名称列缺失时按空串补齐；行键不完整或品相非法 → 400（整批不落库） |

**验收**

1. 历史订单按「国家 + 年份 + 面值」（统一后）去重后逐行展示；三者缺一的订单**不出现**。
2. 国家统一：`英属新西兰` → `新西兰`、`英属澳大利亚` → `澳大利亚`；年份统一：`1910年` → `1910`；
   面值统一：`1便士` → `1 便士`、`一分` → `1 分`、`二十文` → `20 文`；
   年号纪年取年份数字（`康德四年` → `4`、`明治十五年` → `15`）；认不出前导数字的面值（`当制钱十文`）**原样保留**。
3. 统一后的**同值不同写法合并成一行**（`1910` 与 `1910年`、`1便士` 与 `1 便士`、`英属新西兰` 与 `新西兰`）。
4. 四个条件可单独或组合查询、宽松包含；国家 / 年份 / 面值查询词按同一口径统一（输入 `1910年` 命中 `1910`）；品相按 好 / 普通 / 差 精确匹配。
5. 可**手工新增**历史订单里没有的组合（四项必填），新增后出现在列表里（订单数 0）。
6. 品相列是下拉（好 / 普通 / 差，另含「未录入」），已录值回显为选中。
7. 点「保存」写库；重存同一组合为**覆盖**、不新增行；选「未录入」清除该组合。
8. **删除整行需二次确认**（第一次点变「确认删除」+「取消」，再点才提交）；删掉后该组合的历史订单（含不同写法）与品相记录都没了，其余组合不受影响。
9. 品相写独立表，**不改变** `coin_orders`（删除整行例外：那是显式清理）；画像的已有年份由品相决定，推荐结果随之变化。
10. **同国家同年同面值的具名组合互不覆盖**：`(中国, 2015, 5 元, 亚运会, 女排)` 连续保存两次只留 1 行且取后值；
    再存 `(亚运会, 男排)` 新增 1 行；旧的 `(中国, 2015, 5 元, '', '')` 行仍保留。
    v26 老库升到 v27 后旧行的 `theme` / `coin_name` 为 `''`，唯一索引为 5 列，重复启动不报错、不重复回填。

## 14.17 收藏画像与三层推荐（铜币与流通纪念币）

> 定位：把「Numista 目录 + 人工品相」合成**收藏系列画像**，以「系列完整性」和「品相升级」
> 为核心，生成三层优先级的目标购买推荐。配置了收藏系列映射后，每日拍卖匹配由本节驱动；
> 未配置时回退到 §14.2 的标签画像（兼容旧数据）。

### 14.17.1 数据清洗与分档

- **材质**：保留 `Bronze` / `Copper`（含中文「青铜」「铜」）；`Copper-nickel`、银、镍等剔除。
  **纪念币（`object_type` 含「纪念 / commemorative」）不看材质**：中国流通纪念币多为镍包钢 / 黄铜 /
  双色铜合金，单看材质会被全部剔掉；这条旁路同时用于画像成员、映射候选池与 P5 探索候选。
- **精制币**：`is_proof=1`，或**单版**备注 / 版别里出现 `Proof` / `精制` → 剔除。
  系列级描述不参与判断（一个系列有精制版，不代表所有年份都是精制）。
- **尺寸分档**：中 `[25, 30)`、大 `[30, 35)`、超大 `[35, ∞)`；`<25mm` 归「小」，保证每个年份都有档位。

### 14.17.2 系列合并与手工映射

- Numista 系列划分过细，引入**收藏系列**（自定义 `collection_series_id`）。
- 合并规则：**同国家 + 同执政者 + 同面值 + 尺寸差 ≤ 2mm**；名称默认「国家 · 执政者 · 面值」。
- **发行系列 / 发行主题挂在币库系列上**：`coin_series[_cn]` 新增人工字段 `issue_series` / `issue_theme`
  （系列详情页编辑，采集不覆盖），与 Numista 的「所属系列 / 纪念主题」并列展示。
  收藏系列只是**分组容器**（如 `亚运会` 下含 `女排` / `男排` 两个成员），
  画像**按收藏系列汇总**（一个收藏系列一张卡），唯一键是 **(年份, 发行主题)**：
  年份标签写作 `年份(发行主题)`（如 `1993(大熊猫)`），同一年不同发行主题各算一枚
  （珍稀动物系列 10 枚不会塌缩成 6 个年份）；品相匹配按**成员**的系列进行，互不串。
  收藏系列成员表不再保存主题 / 名称（旧列保留但停用）。
- 映射表是**手工维护**的：`coin_collection_series` + `coin_collection_series_members`，
  一个 Numista series 只能属于一个收藏系列；页面 `/coins/collections` 可新建、增删成员，
  纪念币候选与成员展示「Numista series + 国家 + 发行系列 + 发行主题 + 年份范围 + 面值 + 材质 / 尺寸」，
  非纪念币保持原有展示。
- 未被映射的青铜 / 铜系列按同一合并规则自动成组，只用于第三层探索推荐。

### 14.17.3 画像结构

每个收藏系列输出一张画像（成员只用于品相匹配与年份名称标注）：

| 字段 | 说明 |
|---|---|
| 系列名 | 收藏系列名（如「中国 · 5 元」） |
| 发行主题 | 纪念币取成员系列的人工字段，仅用于品相匹配与年份标签，画像不单独汇总 |
| 年份跨度 | 该系列全部成员单版的最早 / 最晚年份 |
| 年份列表 / 条目数 | 按 **(年份, 名称)** 去重后的条目（已剔除精制年份）；标签为 `年份(名称)`，成员无名称时只显示年份 |
| 已有年份 | 各成员人工品相为 好 / 普通 / 差 的年份并集（系列有公历年时按公历年关联）；未录入 = 有订单但实物缺失，不算已有 |
| 缺失年份 | 年份列表 − 已有年份 |
| 需升级年份 | 已有年份中**人工品相为「差」**的年份 |
| 年份规格字典 | `{ "年份(名称)": { mintage, rarity, size, weight, price_estimates: {VF, XF}, comment } }`；同一 (年份, 名称) 在多个成员 / 普制版别间取发行量最大的一条；`comment` 取 `coin_issues_cn.comment` |
| 尺寸档位 | 全部成员系列尺寸中位数对应的档位（收藏系列显式填了尺寸则用显式值） |

年份规格字典的表格里，缺失年份行与需升级年份行用不同底色标记。

匹配口径：国家 / 年份 / 面值先按 §14.16 的 Numista 口径统一，再做宽松包含；
**纪念币按 国家 + 面值 + 年份 + 发行主题 匹配品相**（发行主题为空时不比较主题，历史空串品相行行为不变）；
**非纪念币只按 国家 + 年份 + 面值 匹配**；
系列里有公历年（`gregorian_year`）时**按公历年关联**（明治 6 年 = 1873、大正 6 年 = 1917），
品相记录本身没有公历年（裸数字）才退回年号数字。
`rarity` = Numista Frequency / 100（0.6% → 0.006）。

### 14.17.4 推荐优先级（P1 → P2 → P4 → P5）

**优先级 1：缺失年份补齐**

- 遍历 `missing_years`，生成「国家 + 年份 + 面值」搜索词。
- 排序 = 收藏位置权重 × 稀缺权重。
- 收藏位置权重：系列首年 / 末年 / 执政者更替年 = 1.5，其他 = 1.0。
- 稀缺权重 = `1 / max(rarity, 0.005)`；没有 Frequency 时按 1.0（中性）。
- 展示：年份、发行量、稀有度、尺寸 / 重量、VF / XF 参考价。

**优先级 2：差品升级**

- 遍历 `upgrade_years`（仅人工品相「差」），生成搜索词。
- 排序 = 品相敏感度 × `1 / rarity`；敏感度 = `XF / VF`（仅用于排序）。
- 每个收藏系列最多取前 3 个，整体排在优先级 1 之后。

**优先级 4：跨系列相似推荐（年份匹配）**

- 仅当前两层推荐与当日入库拍品的**匹配条数** < `min_results` 时触发（没有当日拍品时按推荐项数兜底判断）。
- 相似度满足其一：同尺寸档位且尺寸差 ≤ 2mm；面值属于同一层级（配置
  `coins.collection.denomination_tiers`，如 Penny 与 10 centimes）；同执政者，或历史时期重叠 ≥ 50%。
- 候选来自**探索候选池**（`coin_explore_candidates` 中状态为「候选 / 采纳」的系列，忽略除外），
  只取它们的缺失年份；候选池通过目录扫描产生，由 `/coins/explore` 管理。
- 排序：尺寸差升序 → 稀有度降序。
- **先匹配再取数**：P4 候选逐条与当日拍品匹配（标题需同时命中国家、年份、面值），
  排除已被精准匹配（P1/P2）命中的拍品；第一轮不同系列各出 1 条、每卡挂 1 条拍品，
  相似推荐卡最多 20 张；不同系列不足 `min_results` 时第二轮把同系列更多拍品**追加到该系列卡**
  （不新开卡），拍品总数补到 `min_results`（默认 5）；同一条拍品只归属一条相似推荐；卡片标签为「年份匹配」。
- 页面「相似推荐」按每页 5 项分页展示，与精准匹配的分页互不影响。

**优先级 5：面值探索（兜底）**

- 仅当 P4 命中数不足 `min_results` 时触发，用剩下的名额补齐。
- 候选与 P4 同源，但匹配口径放宽为**国家 + 面值**，不要求年份命中；系列去重与两轮补满规则同 P4
  （第二轮追加到同系列卡）。**搜索词只拼国家 + 面值，不带年份**；已被精准匹配或其它相似推荐
  占用的拍品不再使用。
- 卡片标签为「面值探索」，表示「同一国家同一面值、不同年份 / 系列，值得看看」。

**探索候选池扫描（`python -m app.cli coins-explore`）**

- 不依赖收藏画像种子，直接用目录列表页的服务端筛选拉候选（`/catalogue/index.php`，参数见
  `coins.collection.explore_catalogue`：`issuer`（`e`，发行方）、`collectible_type`（`st`）、
  `year`、`composition_id`、`diameter_mm`；空值表示该条件不限）；
- 列表已带材质 / 重量 / 直径，先本地过滤：材质为铜 / 青铜、本地未采集过；
- 合格项再取详情与年份，写入 `coin_explore_candidates`，状态默认「候选」；重新扫描保留已有状态，忽略的不复活；
- 入库时同步做中文（词表 + 大模型兜底）并把正 / 反图缓存到 `data/coin_images/`；

### 14.17.5 年份翻译与拍品匹配

- 推荐生成搜索词时，年份要**翻译回站点写法**：
  - 日本：Numista `year=6` + 公历 1873 → `明治6年`、`明治六年`（另附 `1873` 便于匹配公历写法）。
  - 其他：原年份 + 公历（若不同）。
- 面值同时生成「原样 / 去空格 / 阿拉伯数字转中文」三种写法（如 `2 钱` → `2钱`、`二钱`）；
  站点音译与 Numista 词表不一致时两边都生成（如 `莱普塔` ↔ `雷普塔`），避免相似推荐明明有拍品却匹配不上。
- **采集只抓当日场次**：实时专场按 `start_time`（今日开拍）、限时专场按 `end_time`（今日截拍）落在业务时区今天才拉详情；
  推荐项只与这些已入库拍品匹配（标题需同时命中国家、年份、面值；P5 面值探索只要求国家 + 面值）。
- **名称是精准匹配的硬门槛**：成员填了 `coin_name`（如 `女排`）时，标题必须命中名称，缺名称不判精准
  （P5 也适用）；`theme` 只加分、不单独命中。主题词（如 `亚运会`）在标题里高频且跨国家，不单独作门槛；
  名称未填的成员退回「国家 + 面值 + 年份」。

## 14.18 拍场数据分析（要回答什么问题）

> 状态标记：✅ 现有数据即可做 ｜ ⚠️ 部分可行，结论需标注口径 ｜ ❌ 缺数据，先补再分析 ｜ ⏸ 方法可行但采集暂缓

### 14.18.1 能力边界

当前库是**行情快照**，不是行情时序：

| 已有数据 | 存放位置 | 关键局限 |
|---|---|---|
| 专场：状态、live/timed、开拍或截拍时间、围观数、保证金、拍品数 | `coin_sessions` | 每次采集覆盖写，只留最新值 |
| 拍品：起拍价、当前价、终态（成交/流拍、成交价、中拍人、终态时间）、标签、匹配分 | `coin_lots` | 覆盖写，无价格历史；`closed_at` 是场次截拍时刻，不是逐件落槌时间 |
| 成交样本：标题 + 成交价（按关键词命中） | `coin_price_refs.raw`（JSON） | 仅为单条推荐价取证，未结构化、未全局去重 |
| 出价明细（`uid / name / price / time / is_proxy / status`） | **库内没有**：`auction.get` 带 `item_id` 时才返回 `data.bids` | 只能逐件回采（一场 = 拍品数次请求）；时间无年份、分钟级。2026-10-21 决定暂缓 |
| 币种目录：发行量、稀有度 Frequency、各品相估值 | `coin_issues` / `coin_issue_values` | 干净可用，是最好的价格基准 |
| 自己的历史订单与人工品相 | `coin_orders` / `coin_purchase_grades` | 可关联到具体系列，目前未关联 |
| 站点分类：`cate_id_1` / `cate_id_2` | `coin_lots.category_code` + `coin_categories`（v21） | 分类由**卖家手选**，存在误标；名称靠人工字典（站点无分类列表接口，覆盖率约 1%） |

推论：现阶段**横截面分析可做；成交率与流拍已由终态回采补齐**（每场 1 次详情，见 plan §18.18）。
出价时序虽然能事后取（`bids` 实测可行），但需逐件请求，**暂缓**；只有实时提醒才需要高频轮询。

### 14.18.7 F. 自动化输出

- 周报：新上架的稀有年份、异常溢价（成交价 > 历史 p75 × 1.5）、流拍后降价重挂、店铺新专场。
- 盘前提示：今日截拍专场里「缺口年份 + 价格在区间内」的拍品。
- 状态：⚠️ 币种映射已落地（P0-4）；成交率 / 流拍与成交明细已就绪。

### 14.18.8 统计口径与陷阱

- **选择偏差**：站内成交搜索只返回成交条目；均价类结论必须标注为「成交样本均价」，不等同于市场价。
- **小样本**：单币种单年份的成交往往只有个位数，分组统计需给出样本数。
- **重复条目**：同一成交会因多个关键词重复命中；聚合前必须去重，优先用 `item_id`。
- **成交时间口径**：限时专场的 `item.end_time` 等于专场截拍时刻，**不是逐件落槌时间**；「最后 N 分钟」只能用 `bids` 或快照。
- **出价时间口径**：`bids.time` 形如「10-21 13:08」，无年份、只到分钟；跨年场次用专场结束时间推断年份。
- **出价人身份**：人数按 `bids.uid` 去重，不按昵称；中拍人用 `won_user_id`，匿名昵称不可作键。
- **到手价口径**：到手价 = 成交价 + 佣金（费率 × 成交价与最低佣金取高）+ 基础运费（成交价达满额包邮门槛则免）；不含保险费、汇率与地区运费差异。
- **时间口径**：库内时间为 UTC ISO8601，展示按 `config.app.tz` 转换。
- **覆盖写残留**：`fetched_at` 是最后采集时间，不能反推「首次出现时间」。

## 14.19 硬币分类与分析页（口径与验收）

> 实现细节与实测数据见 plan/coins.md §18.19。本节只定义**要什么、怎么算、什么算做完**。

### 14.19.1 范围

- 只做**硬币**（站点一级分类 `11000`）；其他一级分类只入字典，不做页面。
- 只关注**裸币**：品相分级与评级分数不做；仅用「是否评级盒」（`is_graded`）把评级盒排除。
- 不改采集节奏、不动定价链路；分类与 `is_graded` 只作为筛选与分组维度。

### 14.19.2 分类口径

- 每个拍品只记**最细一级**的站点原始码（`cate_id_2` 优先，缺失回落 `cate_id_1`，0 视为未分类）。
- 一级分类由码前缀推导（前 3 位 + `00`），名称统一查 `coin_categories` 字典，不在拍品行冗余名称。
- 分类是卖家手选，**不保证正确**：分析页的错标抽查只做展示，不回写、不纠正分类码。
- 名称字典由人工维护（站点没有分类列表接口）；字典外的码以码为名兜底并记录，等待补字典。

### 14.19.3 分析页要回答的问题

页面 `/coins/analysis`，默认筛选「硬币 + 裸币」，支持切二级分类与时间窗。样本数 < 5 的分组一律标「样本不足」，不给结论。

| 分组 | 要回答的问题 |
|---|---|
| 概览 | 各二级分类的上架量与成交率差多少，哪个分类最难卖 |
| 价格 | 各分类的成交价中位数与 p25–p75 区间；与 Numista 估值的比值（标注映射覆盖率） |
| 成交与流拍 | 起拍价档位与成交率的关系；流拍后是否降价重挂、间隔多久 |
| 店铺画像 | 哪家店上架多、成交率高、价格稳；复现率是否异常 |
| 供给与重复 | 哪些分类供给过剩；同图重复（描述图复用）占比；分类与标题明显冲突的错标样本 |

### 14.19.4 统计口径

- **成交率** = 成交拍品数 /（成交 + 流拍），分母**不含在拍**；在拍拍品不参与任何成交率计算。
- **价格**一律用**中位数**并附样本数；不展示仅由 1–2 条样本算出的均值。
- **成交样本均价 ≠ 市场价**：只代表本平台已成交样本，结论必须带此限定。
- **重复条目**按 `item_id` 去重；同图识别按 OSS key，但跨场复用的描述图需单独标注，不能直接当作「同一枚币」。
- **店铺口径**是「我们见过的场次」，不是店铺全量成交额。

### 14.19.5 验收标准

1. 新库初始化后 `schema_version = 22`，`coin_lots.category_code`、`coin_lots.is_graded` 与 `coin_categories` 均存在；v20 / v21 老库可幂等升级。
2. 新采硬币专场分类非空率 ≥ 95%；硬币二级 9 个分类名称在字典中齐全。
3. 历史回填后分类有值占比 ≥ 90%，且不存在字典外的裸码。
4. `/coins/analysis` 返回 200，默认只统计硬币裸币；切换二级分类后各 Tab 数字随之变化。
5. 样本不足分组显示占位文案；均价均为中位数且带样本数。
6. 现有 `/coins`、`/coins/session/{id}`、`/coins/manage`、`/coins/collection` 无回归。

### 14.19.6 本轮不做

品相细分与评级分数、时间趋势、Numista 估值深度对比、出价时序、店铺粉丝与历史总成交额、起拍折扣建模、非硬币分类页面。
