# 文档增补规程

> 从 [RULES.md](../RULES.md) §六 分册出来的专题细则；判据仍在 RULES，本文只讲「往哪个文件、怎么写」。
> spec / plan 只写「现在是什么样」；只有 CHANGELOG 写「什么时候变成了这样」。

## 1. 往哪写

| 文档 | 性质 | 增补时怎么动 |
|---|---|---|
| `spec.md` / `plan.md`（索引）+ `spec/` / `plan/`（分册） | 状态快照 | **原地改写**受影响正文；不新增「vX.Y 增补」小节、不留旧文本 |
| `CHANGELOG.md` | 时间线 | 只追加一条：起因 → 改了什么 → 实测结论 → 影响文件 |
| `tasks/<模块>.md` | 任务与验证证据 | 加 / 勾任务行；过程叙述写进 CHANGELOG |

## 2. 通用约定

1. **版本号不进 spec / plan 标题**：`v1.6`、日期这类只出现在 CHANGELOG 与 tasks。
2. **同一事实只写一处**：需求在 `spec/`，实现在 `plan/`，用法在 `README.md`，变更在 `CHANGELOG.md`；重复时删掉非本处那份，保留链接。
3. **编号是锚点：不复用、不重排**。新增小节编号顺延（如 `§18.16`），既有编号只改内容不改号；确需重排时同一次提交改完全部引用。
4. **单文件 ≤64KB**、单轮输出 ≤200 行（RULES §四）同时成立；超了先拆分册。
5. **代码与文档同一次提交**，`spec ↔ plan ↔ tasks ↔ README` 不得静默跑偏；实现与文档冲突时改文档。

## 3. 分册与编号

- `spec/` / `plan/` 下按模块成文（`core` / `knowledge` / `coins`），`spec.md` / `plan.md` 只是索引。
- 编号全局唯一（`§14.x` 铜币需求、`§18.x` 铜币实现、`§5`~`§8` 知识聚合），跨文件引用写全路径。
- 只做某模块时只读该模块分册 + 按需读 `core`。
